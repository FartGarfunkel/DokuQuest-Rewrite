# Part 2 — Stone age Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The immersive world rule; trees need an axe; leaves you fall through; rocks, flint and twigs on the ground;
knapping (5×5) into stone and flint tool heads; head + stick tools; the classic early tool recipes off in immersive worlds.

**Architecture:** A rule `immersive` (default false for old saves; Create World sets it true). Pure sim modules:
`sim/knapping.{h,cpp}` (patterns from `data/knapping.json`, matching with offsets and mirroring, the knap session state),
`sim/immersive.{h,cpp}` (the rule's gates: log harvest, leaves passable, recipe filter, leaf stick drops). A knapping
screen `ui/knapping_screen.cpp` opened through `openScreen(lv, p, "knapping", {material})`. New items/blocks in
`data/items.json`, `data/blocks.json`, `data/recipes.json`, generated by `tools/port/immersive_data.py` (one script, rerun
safely: skips keys that exist).

**Spec:** `docs/superpowers/specs/2026-11-10-immersive-progression-design.md` (Part 2)

## Global Constraints

- Classic worlds unchanged (every gate checks `rule(lv, "immersive")`), except new ground decorations (see Ruling R1).
- Controller: knapping grid fully usable with d-pad/stick + A/B.
- One feature per file < ~1500 lines; no static-constructor registration.

## Review Focus

1. An old save (no `immersive` key) must behave exactly as before: logs by hand, wooden tool recipes.
2. Knapping with exactly 2 stones; closing the screen mid-way (the first chip's stone is spent, nothing else).
3. A pattern matched at the grid's edge and mirrored (axe head facing left or right).
4. Leaves passable but still breakable/placeable; mobs and the player falling into a tree take no fall damage
   beyond what the slowed fall gives.
5. Multiplayer: knapping writes the inventory directly (as the sign screen does); a remote client is out of scope here.

## Rulings made while planning
- R1: Ground twigs/flint/denser rocks generate in every new chunk (classic too): harmless, and worldgen has no rule access.
- R2: Pebble knapping → new `stone_*_head` items; flint knapping → the existing `flint_*_head` items (flint tools are
  better, tier 2, as now). Tools from heads keep our existing stats (stone tools tier 2, durability 132) — not TFC's
  50–70 — to keep it from being hard.
- R3: Only wooden-tool and cobblestone-tool recipes are switched off in Part 2; metal tool recipes are switched off in
  Part 4 when smithing exists (so an immersive world is never without a path).
- R4: The crude pickaxe is tier 2 like stone tools (our tier 2 includes iron ore; iron still needs the bloomery, Part 4),
  durability 40, speed 3.
- R5: Javelin is a melee weapon for now (no throwing system yet).

### Task 3: Knapping rules and data
**Files:** `data/knapping.json` (new: `{"stone": [{out, n, pattern[5 strings], from: ["pebble"]}], "flint": [...],
"clay": []}` — TFC's shapes with `#` = kept: axe, shovel, hoe, knife ×1, knife ×2, hammer, javelin, plus crude pickaxe
`"#####"," # # ","  #  "`-like (top bar, centre post)); `src/sim/knapping.{h,cpp}`; tests in `tools/test_immersive.cpp`.
**Interfaces:**
```cpp
struct KnapPattern { std::string out; int n; std::vector<std::string> rows; };   // '#' kept, ' ' removed
const std::vector<KnapPattern>& knapPatterns(const std::string& material);     // "stone" | "flint" | "clay"
std::string knapMaterialOf(const std::string& itemId);                          // pebble -> stone, flint -> flint, clay_ball -> clay, "" otherwise
int knapCost(const std::string& material);                                      // stone/flint: 1 (the first chip), clay: 5 (on a match)
struct KnapGrid { std::array<bool, 25> kept; };                                 // all true at start
const KnapPattern* knapMatch(const std::string& material, const KnapGrid& g);   // a pattern whose kept cells equal the grid's, at any offset, mirrored too; cells outside the pattern's box must be removed
```
- [ ] Tests first: a full grid matches nothing; the axe pattern carved at offset (0,0) and at (bottom-right) matches
  `stone_axe_head`; its mirror image matches too; one extra cell removed → no match; `knapMaterialOf("pebble") ==
  "stone"`; every pattern in the file is 5 wide or narrower and all patterns in one material are distinct.
- [ ] Run → FAIL; implement; run → PASS; ledger.

### Task 5: The knapping screen
**Files:** `src/ui/knapping_screen.cpp` (new), `src/ui/ui_main.cpp` (`onScreenOpen` kind "knapping"),
`src/sim/controller.cpp` (use on air or the ground with ≥2 of a knappable item → `openScreen(lv, p, "knapping",
{{"material", m}, {"item", held.id}})`; clay needs 5).
- [ ] The screen: a 5×5 grid of the material's picture (stone: the pebble's tile; flint: flint; clay: clay) on a dark

  listens on the EventBus).
